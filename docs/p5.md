# P5. Версионирование опубликованных результатов

Используется `mike`. Версии `v1.0` и `v1.1` публикуются в ветку `gh-pages`, алиас `latest` указывает на последнюю версию.

## Настройка

- `mkdocs.yml`: `extra.version.provider: mike` добавляет переключатель версий.
- `.github/workflows/versions.yml`: срабатывает на тег `v*`, вызывает
  `mike deploy --push --update-aliases <тег> latest` и `mike set-default latest`.

## Как выпустить версию

```bash
git tag v1.1
git push --tags
```

## Проверка русского поиска

В `mkdocs.yml` включён `search.lang: ru`. Проверка выполнена на опубликованной версии `latest`: в строку поиска вводился запрос, затем смотрелось, подсвечена ли искомая словоформа в найденных страницах.

| Запрос | Искомая словоформа | Подсвечена? | Комментарий |
|---|---|---|---|
| регрессия | регрессионный | нет | найдены страницы только с точным словом «регрессия» |
| модель | моделирование | нет | подсвечено только слово «модель» |
| график | графиков | да | подсвечены «график» и «графиков» |
| измерение | измерения | нет | подсвечена другая форма, «измерением» на странице T1 |
| версия | версионирование | нет | подсвечена другая форма, «версиями» на странице хода работы |

Вывод: поиск справляется с изменением окончаний (графиков, измерением, версиями), но не связывает слова с одним корнем и разными суффиксами (регрессионный, моделирование, версионирование). Стеммер не делает морфологического разбора.

Ограничения проверки:

- запросы вводились по одному разу, а искомые слова взяты из самой этой таблицы, поэтому часть совпадений приходится на неё же;
- результат определялся по подсветке в поисковой выдаче, а не по анализу индекса.
