# Вывод

## Рекомендуемый стек

Для публикации результатов небольшого эксперимента с русским текстом: **MkDocs + Material**, версии через **`mike`**, сборка и публикация в **GitHub Actions**, доставка на Helios через **`rsync` по SSH** с отдельным deploy-ключом и проверкой ключа хоста.

Почему так:

- MkDocs собирает сайт за секунды и настраивается одним `mkdocs.yml`;
- версии и переключатель версий работают с `mike` без дополнительной вёрстки;
- режим `--strict` не даёт опубликовать сайт с битыми ссылками;
- формулы и шрифты лежат в репозитории, сайт не зависит от внешних CDN.

## Что выяснилось по ходу работы

- По сумме баллов в [T1](t1.md) Sphinx впереди (49 против 44), но MkDocs выбран из-за версий и русского поиска, которые нужны для P5.
- Русский поиск корректно обрабатывает смену окончаний, но не связывает слова с разными суффиксами ([P5](p5.md)).
- Pages из Actions и `mike` не совмещаются без доработки: источник Pages — либо Actions, либо ветка.
- Helios доступен из облачных раннеров GitHub по порту 2222, `rsync` на сервере есть, адрес по `http` перенаправляет на `https`.

## Когда рекомендация меняется

- Нужны нумерованные формулы и рисунки с перекрёстными ссылками, BibTeX, PDF — Sphinx с MyST.
- Нужно исполнять ноутбуки при сборке — MyST-NB или Quarto.
- Нужен простой блог без научного оформления — Pelican или Nikola.
- Нужен более точный русский поиск, чем стемминг по окончаниям — внешний поисковый сервис.
- Хостинг закрыт от раннеров GitHub — self-hosted раннер или другой хостинг.

## Что не проверялось

- Lighthouse и вёрстка на мобильных экранах.
- Quarto: не ставится через pip.
- Замеры времени в T1 сделаны одним запуском на одной странице.
